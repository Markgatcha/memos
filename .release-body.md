# memos v1.6.27

Stable release bumping `package.json` from `1.6.26` to **`1.6.27`** — 362 commits since v1.6.26, all curated in the [CHANGELOG](https://github.com/Markgatcha/memos/blob/main/CHANGELOG.md).

Headline: **image memory (vision)** — images are now first-class memories with optional CLIP pixel search — plus the two-stage reranker, the full 14-tool MCP surface, RRF hybrid retrieval fusion, token-lean pack defaults, and Python 3.15 support.

## What's new in this release

### Added — Image memory (vision)

Images are now first-class memories. An image memory is an **ordinary memory node** whose `content` is a caption, plus the bytes in a content-addressed blob store (`<dbDir>/memos-images/`). No new `MemoryType` member: `metadata.image` is the discriminator, so the sync allowlist, fidelity labels, adapters, and MCP schema all keep working unchanged.

- **Write API** — `addImageMemory(input, opts)` normalizes every input shape (path, URL, `{ data, mime }` base64, `data:` URL, raw bytes), writes the blob, and routes the caption through the normal store pipeline — quarantine screening, provenance, auto-linking, contradiction scan, and the tamper log all apply for free. Identical bytes dedupe to one blob.
- **Two retrieval tracks, independent** — *Track A (always on)*: the caption is embedded by your normal text embedder, so keyword + semantic search find images with zero extra downloads. *Track B (opt-in via `vision.clip.enabled`)*: the image itself is encoded by CLIP into a separate vector space, so a query can match the pixels when its wording differs from the caption's. Fails soft to Track A; never throws, never substitutes a text vector.
- **Read API** — `searchImages(query, opts)` fuses the caption leg and the CLIP leg by reciprocal rank; `imageMemory(ref)` resolves an `[img:…]` ref back to bytes.
- **Accuracy invariants** — `[img:<ref>]` tokens are pinned in `compressText` and appended at every fidelity level (L0–L3); a CLIP-only hit now counts as embedding evidence for the relevance gate.
- **Surfaces** — CLI `memos image add|list|search|show|purge`; MCP tools `memos_image_add` / `memos_image_search` / `memos_image_recall`.
- **Disabled by default** — a bare `new MemOS()` creates the (empty) `image_embeddings` table and nothing else: no new API surface, no changed search results, no changed pack bytes.

### Added — retrieval & distribution highlights

- **Two-stage reranking** (`experimental.rerank`) — cross-encoder re-scoring after fusion. Measured on LoCoMo convs 0–1: Hit@10 68.2% → 81.1%, EvRec@10 63.4% → 75.5%, MRR 0.469 → 0.606.
- **MCP full capability surface: 6 → 14 tools** — `memos_context_pack`, `memos_search_temporal`, `memos_set_validity`, `memos_supersede`, `memos_set_trust`, `memos_extract_facts`, `memos_diagnostics`, `memos_reindex` and more, upgraded to the 2026-07-28 protocol revision with dual-era compatibility.
- **RRF hybrid fusion** — the fusion logic is now a pure, exported `fuseResults()`; plus the FTS5 tokenization fix (the keyword leg previously returned zero rows for natural-language queries) and a search-cache key fix that covered only 6 of ~15 filter fields.
- **Token-lean defaults** — `memos_context_pack` serializes as toon-compact by default (~70% fewer tokens); `memos_search` accepts `compact: true`.
- **`memos doctor`** — one-command health check; **`memos connect <target>`** — registers the stdio MCP server with any harness; **Claude Code plugin + marketplace**; memory-haystack and HotPotQA benchmarks.
- **Performance** — in-memory vector cache, auto-link edge cap (12.7× faster ingestion on repetitive corpora), zero-copy Float32Array vector decoding, rerank server batching (~7–10×).
- **Python 3.15 support** — declared and exercised in CI (3.11–3.15, 5/5 green), UTF-8 pinned on the backup manifest per PEP 686.
- **Full-dataset LoCoMo re-run** — 83.2% Hit@10 / 77.9% EvRec@10 at 79.7 min instead of 266.6 min (3.3×) with the fast config.

### Fixed

- **Flaky `EmbeddingQueue` concurrency test** — now asserts the observable high-water mark (`peakInFlight === 4`) instead of wall-clock elapsed time; mutation-verified and stable across 5 consecutive runs.
- **4 CodeQL ReDoS alerts** resolved; `search()` no longer stamps `updatedAt` on recalled nodes (Ebbinghaus reinforcement side effect).
- **Search-dispatch bug** — the hybrid multi-leg path now triggers when the CLIP image leg can contribute, not only when a text embedder is configured.
