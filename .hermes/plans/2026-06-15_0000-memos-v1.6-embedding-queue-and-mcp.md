## Goal
Ship a non-blocking background embedding queue, bring the MCP server to the 2025-06-18 spec that `@universal-mcp-toolkit/core` and the AI Trio expect, implement the `ai-trio.memos.context-pack.v1` contract for LLM Guardian, ship concrete perf wins and small fixes, and update the changelog/roadmap.

## Architecture

**Embedding queue** lives in a new `src/embedding-queue.ts` module. It is a fixed-size worker pool (default 2) with bounded retries (default 3, exponential backoff), a max queue depth (default 10 000), and four lifecycle events: `embedding:queued`, `embedding:started`, `embedding:complete`, `embedding:failed`. `MemOS` owns one queue per instance, starts it lazily on first `enqueue`, and drains it on `close()`. `store()` and `update()` enqueue but return immediately. New SDK methods: `flushEmbeddings()`, `embeddingStatus()`. A new column `embedding_status` (TEXT, default 'pending') tracks per-node status so the queue can recover after restart and so observers can see what's stuck.

**MCP 2025-06-18 / UMT compat**: protocolVersion bumped to `2025-06-18`, `serverInfo.version` pulled from `package.json` at build time, server-side `memos_context_pack` tool that calls the SDK `contextPack()` method and returns the AI Trio v1 JSON envelope (NOT wrapped in MCP `content[]` — context pack is structured content). New tools: `memos_flush_embeddings`, `memos_embedding_status`. New events on the MCP wire follow the spec.

**LLM Guardian compat**: implement `memos.contextPack(query, options)` exactly per `docs/ai-trio-contracts.md` — sort by descending relevance, plain text content, preserve `trust`/`source`/`tags`/`updatedAt`, deterministic for same DB+query+provider+model. Trust defaults to `"local"` and source defaults to `"session"` since the v1 contract requires them.

**Perf wins**: (1) one-pass cosine, (2) heap-based top-k in `querySimilarEmbeddings` so we don't sort the whole result set, (3) `evict()` becomes a single SQL `DELETE … ORDER BY importance ASC, last_accessed ASC LIMIT 1`, (4) `getNode` debounces access tracking to one write per N ms so reads stop hammering SQLite WAL, (5) `autoLink` caches the bag-of-words set per node.

**Fixes**: (1) `tag`/`untag` re-fetch via `getNode` was incrementing access count as a side effect — replace with a side-effect-free read, (2) MCP `memos_store` was silently dropping `metadata`/`importance`/`summary`, (3) MCP version was hardcoded "1.5.0", (4) Python server's bridge script temp path was shared across users — use a per-user dir, (5) stop-words list was duplicated in `graph.ts` and `memory.ts` — already fixed in 1.5.0, but verify.
